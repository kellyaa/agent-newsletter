  title: "ConsistencyGate: Preventing Memory Contamination in LLM Agents via Self-Consistency Admission Control"
  author: "Yan Zhang, Shibo Li"
  score: 8
  tags:
  - "memory"
  - "safety"
  summary: "Existing agent memory management handles retrieval and capacity but never write-time correctness, so a hallucinated fact persists as a false premise for every downstream step. ConsistencyGate is a write-time admission gate: before committing a candidate fact, it queries the model K times for a soft support score and only admits above a threshold, with a single-forward-pass log-prob variant for latency-sensitive use. It's model-agnostic and needs no fine-tuning. Across four backbones and two new planted-corruption benchmarks (LoCoMo-Contam, MSC-Contam) it beats write-everything, with cost concentrated on implicitly-stated facts."
  takeaway: "If your agent writes facts to long-term memory, add a write-time consistency check — retrieval-side filtering can't undo a false premise already committed."

  summary: "A sharp result for anyone evicting KV-cache as agent memory. The authors omit an earlier observation from what's served, and downstream answers still follow the omitted value even though no served span states it — they call this semantic materialization: a later event's cached rows act as a servable view of computation whose inputs are gone. A deliberately phrased answer-free event lifts donor-aligned recovery from 6% to 51% on Qwen3-8B. Compact state survives; larger payloads decay toward chance; whether a row writes turns on phrasing, not meaning."

  summary: "A screenshot is a lossy render of program state — files, backends, DOM — and different states produce identical pixels. StateAct is a code-first harness where the main agent manipulates state directly and delegates screenshot-and-click to a GUI subagent only when needed (28 of 108 tasks, 1.1% of steps), with an independent finish gate checking for missing or misplaced output. On OSWorld 2.0 it lifts Claude Opus 4.8 from 20.6% to 26.9% binary success at ~9x lower cost per task; a code-only variant underperforms the screenshot baseline, so the GUI fallback matters."
  takeaway: "For computer-use agents, spend on grounding actions in inspectable program state rather than better perception — but keep a screenshot fallback for the subgoals that genuinely need pixels."
