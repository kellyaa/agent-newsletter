# Roadmap

Planning artifact from the strategist agent. It proposes priorities and is not a commitment. The issue tracker stays the source of truth for definition-of-done (see SPEC.md §Iteration Plan). Maintainers decide what lands here.

## Where the project is

- Two editions are `live`: `agents` and `engineering-with-ai` (`editions/*/edition.yaml`). `run.sh` runs every non-paused edition, one after another, in a single unattended daily run.
- Multi-edition support (epic #291) has shipped. The scaffolding (`new_edition.py`, `check_edition.py`), the edition-aware site, and the operations guides are in place.
- Recent work has been hardening: refactors that share helpers and constants, test tightening, and docs guides. The latest run single-sources more contracts in `scripts/models.py` and a few shared modules, each pinned by an AST guard test and an `AGENTS.md` rule (#636, #640, #642, #644, #646, #649, #651, #653, #656, #659, #663, #666, #669, #672, #678, #682, #686, #689, #693, #697, #702, #707, #714, #718), plus a watchdog fix so its own checks cannot fail silently (#675).

## Needs a maintainer decision

- **Should an HTTP failure on one rank section fail the whole run?** `call_llm` raises `RuntimeError` for a bad reply, and `rank.rank_section` isolates that per section (#208). An HTTP-level failure (`openai.APIError`: timeout, 429, 5xx) is not a `RuntimeError`, so it fails the rank stage, and one 503 on the papers call loses the day's issue even when news and blogs scored. The architect's options, filed as a folded finding on #711 (closed by #712, which only documents current behaviour in `docs/llm-error-handling-guide.md`), are: (1) normalise in `llm.py` so `call_llm` re-raises `openai.APIError` as `RuntimeError` and rank publishes the sections that did score, with write still failing its stage; or (2) keep fail-fast so `./run.sh --failed` re-runs the day whole, and pin it in the `call_llm` docstring and a test. Option 1 changes what gets published on a bad-endpoint day, which is why it is a maintainer call. The decision was tracked on #715, which was closed as completed three minutes after it was filed, with no `/hive decision` reply and no comment. No decision is recorded and `llm.py` is unchanged, so the behaviour today is the fail-fast option 2, without the `call_llm` docstring note and test that option 2 would add. A maintainer should either confirm option 2 (and reopen or file an issue for the docstring and test) or choose option 1.
