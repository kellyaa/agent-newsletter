# Quality

Where to look to judge the health of this project. Satisfies the ACMM `acmm:quality-dashboard` criterion. There is no hosted dashboard; the signals below are generated by the repository itself.

| Signal | Where | Gate |
| --- | --- | --- |
| Python tests and coverage | `uv run --extra test pytest`; CI workflow `.github/workflows/tests.yml` | 95% (see `pyproject.toml`, mirrored in `.coverage-thresholds.json`) |
| Site tests | `.github/workflows/site-tests.yml`; `site/tests/` | must pass |
| Edition config health | `uv run scripts/check_edition.py <slug>` (lint + dry-run fetch, no LLM) | no errors |
| Pipeline output (items fetched, candidates, featured per day) | `editions/<slug>/state.db` on the `content` branch; columns in [metrics/README.md](metrics/README.md) | featured-per-day trend per edition |
| Run reliability | `run_attempts` table (`outcome`, `failed_stage`) | failures notify the owner per edition |
| Self-tuning thresholds | `.github/auto-qa-tuning.json` | checked by `tests/test_auto_qa_tuning.py` |
| Review standard | [review-rubric.md](review-rubric.md) | applied to every PR |

Lessons from incidents go in [reflections/](reflections/README.md).
