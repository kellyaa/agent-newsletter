### [anthropics/claude-code v2.1.139 + v2.1.141](https://github.com/anthropics/claude-code/releases/tag/v2.1.139)

`gh:anthropics/claude-code` · ▰▰▰▰▰▰▰▰▱▱ 8/10 · `infra` `multi-agent` `devops-agents`

Two releases this week (v2.1.139 and [v2.1.141](https://github.com/anthropics/claude-code/releases/tag/v2.1.141)) ship a dense set of production-relevant primitives. The headline is `claude agents` — a unified dashboard of all sessions (running, blocked, done). `/goal` adds completion-condition semantics: set a target, Claude keeps working across turns until it's met, showing elapsed/turns/tokens as an overlay. On the hook side: `continueOnBlock` for `PostToolUse` lets rejection reasons feed back to Claude instead of hard-stopping, and exec-form hooks now accept `args: string[]` to skip shell quoting issues. v2.1.141 adds workload identity via `ANTHROPIC_WORKSPACE_ID`, hook `terminalSequence` for desktop notifications without a terminal, and a "Summarize up to here" rewind option for context compression mid-session.

> **TAKEAWAY** — If you're running background agents, the new permission-mode preservation on `/bg`-spawned agents and the `continueOnBlock` hook option both patch real friction points worth adopting immediately.

### [openai/openai-agents-python v0.16.0](https://github.com/openai/openai-agents-python/releases/tag/v0.16.0)

`gh:openai/openai-agents-python` · ▰▰▰▰▰▰▰▱▱▱ 7/10 · `frameworks` `multi-agent` `tool-use`

Four behavioral changes with production impact. Default model shifts from `gpt-4.1` to `gpt-5.4-mini`, pulling in GPT-5 defaults (`reasoning.effort="none"`, `verbosity="low"`) for any agent without an explicit model set — silent behavior change. `max_turns=None` disables the turn limit without touching the existing `DEFAULT_MAX_TURNS=10` default. `ToolExecutionConfig(max_function_tool_concurrency=...)` on `RunConfig` now controls SDK-side local function concurrency separately from provider-side `parallel_tool_calls`. MCP tool names can optionally include the server prefix via `include_server_in_tool_names`.

> **TAKEAWAY** — Audit every agent that omits an explicit `model=` before upgrading; the implicit default change will silently alter behavior in ways that may not surface until you hit a reasoning-heavy code path.

### [openai/openai-agents-python v0.17.0](https://github.com/openai/openai-agents-python/releases/tag/v0.17.0)

`gh:openai/openai-agents-python` · ▰▰▰▰▰▰▰▱▱▱ 7/10 · `frameworks` `infra` `safety`

`RealtimeAgent` default flips to `gpt-realtime-2`. The substantive change is a sandbox boundary enforcement fix: `LocalFile.src` and `LocalDir.src` are now constrained to the materialization `base_dir` unless explicitly granted via `SandboxPathGrant`. Previously, absolute host paths outside the base directory could be copied into sandbox workspaces — this closes that. The release includes a migration guide with `extra_path_grants` and `SandboxPathGrant` for applications that intentionally trusted external host roots.

> **TAKEAWAY** — If your sandbox manifests reference absolute host paths outside the SDK process working directory, this is a breaking security fix; apply `SandboxPathGrant` grants before upgrading or your artifact copies will fail.

### [Show HN: Statewright – Visual state machines that make AI agents reliable](https://github.com/statewright/statewright)

`hn:hn-agent` · ▰▰▰▰▰▰▰▱▱▱ 7/10 · `frameworks` `planning` `infra`

Ben Cochran's approach: instead of scaling model size to get reliability, constrain the solution space using formal state machines enforced in Rust. Each state defines which tools the model can access, iteration budgets, and valid transitions — a planning state gets read-only tools, an implementation state gets scoped edit/write/bash, a testing state gets bash-only. The enforcement is protocol-level, not prompt-level. Tested on SWE-bench with 13–20B parameter models across Qwen-coder, GPT-OSS, and Gemma4 families, showing competitive results with models far smaller than frontier size.

> **OPEN QUESTION** — At what task complexity does the state machine schema become as brittle as the prompts it replaces, and how do you version-control agent FSMs alongside the code they operate on?

Eugene Yan's framework for compounding with AI rather than just using it: context as infrastructure (what you give the model determines what it can do), taste as configuration (your judgment curates outputs), verification as the unlock for autonomy (you can delegate more when you trust the eval), and closing the loop (outputs feed back into your context corpus). > **TAKEAWAY** — The "verification for autonomy" framing is the load-bearing idea: if you can't verify an output class, you can't safely delegate it — which means investing in evals before expanding agent scope, not after.

Thariq Shihipar (Claude Code team) argues for HTML over Markdown as the default output format to request from agents — HTML unlocks inline SVG, interactive widgets, in-page navigation, and diff annotations with severity color-coding. The piece includes a prompt for PR review that generates an HTML artifact with inline margin annotations.
